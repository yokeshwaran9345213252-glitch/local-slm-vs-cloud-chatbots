Prompt Engineering Studio (Before vs. After Diffs)

Demonstrating how structured prompt engineering turns an erratic Small Language Model into a deterministic production engine.

❌ Before: Naive Zero-Shot Prompt 58% JSON Pass
"Extract patient info from: 'Patient John Doe, 46M, admitted Oct 24 2024 with acute bronchitis. Prescribed Azithromycin 500mg PO daily. Allergy: Penicillin.' Make it JSON."
Certainly! Here is the JSON for the patient:
```json
{
  "Patient": "John Doe",
  "Age_Gender": "46M",
  "Notes": "Allergic to Penicillin"
}
```
I hope this helps! Let me know if you need more info.

⚠️ Defects: Conversational chatter breaks automated parsers. Non-standard keys. Missing nested structures.

✓ After: Structured Engineered Prompt 100% Valid RFC-8259
"You are a deterministic clinical extractor. Output raw RFC-8259 JSON only matching: {patient: {name, age, gender}, condition, medications: [{drug, dose, route}], allergies: [{substance}]}. Zero filler."
{
  "patient": {"name": "John Doe", "age": 46, "gender": "M"},
  "condition": "acute bronchitis",
  "medications": [{"drug": "Azithromycin", "dose": "500mg", "route": "PO"}],
  "allergies": [{"substance": "Penicillin"}]
}

🌟 Optimization: Zero conversational bloat (saves 32 tokens). 100% machine-executable in standard backend pipelines.
